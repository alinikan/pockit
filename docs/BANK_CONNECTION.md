# Adding a bank connection to Pockit

Pockit currently has **manual transactions and reviewed CSV import**, with no bank account connection. That is deliberate: the current Supabase and Vercel setup can stay free for a few people, while live bank data requires a provider, more server code, and careful account controls. A bank connection is a future feature, not a switch in Supabase.

## Pick the product and check cost first

For Canadian institutions, begin with [Plaid's coverage explorer](https://plaid.com/docs/institutions/) and verify that each bank supports **Transactions**. Coverage varies by institution and account. Create a [Plaid Dashboard](https://dashboard.plaid.com/) account and use **Sandbox** before requesting live access. Plaid's billing docs describe a free Trial with limited Items and a Pay-as-you-go plan. **Transactions is a monthly subscription per connected Item in Production**, and Plaid does not publish a universal price list in the docs; the price is shown during Production access. Check the current terms and your own Dashboard before linking real accounts. A production bank connection may break Pockit's $0 goal. [Plaid billing](https://plaid.com/docs/account/billing/), [Plaid pricing](https://plaid.com/pricing/).

If the cost or institution coverage is unsuitable, keep the **Activity → Import CSV** flow. It needs no bank API, provider approval, or bank credentials. Users should check the sign convention and preview before importing.

## Account and website setup when you choose to build it

1. In the Plaid Dashboard, create an application named Pockit. Enable **Transactions** in Sandbox. Do not enable extra paid products until they have a concrete use. Copy the **client ID** and **Sandbox secret** into a password manager.
2. Test the institution or test bank in Sandbox using [Plaid Link](https://plaid.com/docs/link/web/). Build an HTTPS webhook endpoint in Pockit's Vercel project, for example `https://YOUR-PROJECT.vercel.app/api/plaid/webhook`. Pass this exact URL when creating a Link token. For OAuth banks, also configure the redirect URI in Plaid and implement its browser return flow. Plaid's [Transactions guide](https://plaid.com/docs/transactions/) describes this sequence.
3. In **Vercel → Project → Settings → Environment Variables**, add `PLAID_CLIENT_ID`, `PLAID_SECRET`, and `PLAID_ENV=sandbox` for the server. Use the Sandbox secret during development, then a **different Production secret** after approval. Also add an encryption key for stored Plaid access tokens, generated with a cryptographically secure tool. These are **server-only**; none may begin with `VITE_`, appear in `.env.local` for the Vite browser build, or be committed to GitHub. For local Vercel Function development, use an ignored local server environment file and `vercel dev`.
4. Before requesting Production, open Plaid's Production access flow, inspect the Transactions price for your plan, confirm Canadian institution support, and complete the application requirements. Set up a spending alert or budget in your billing account. Use the Production credentials only after pricing and access are clear.

## Code that must be built before any live connection

The following pieces **are not in this repository yet**. Connecting a real bank safely requires all of them:

1. **Private tables:** add `bank_items` for one row per user and Plaid Item, with an encrypted access token, `item_id`, sync cursor, institution name, and connection status. Add `bank_transactions` with a unique Plaid transaction ID, user/Item reference, pending status, date, payee, amount, user category override, and review status. Enable RLS so users can read only their own transaction rows. Keep Plaid access tokens inaccessible to the browser and to ordinary RLS reads. This relational design is preferable to putting incoming bank updates into Pockit's single JSON budget document: server webhooks and device edits otherwise compete to overwrite one another.
2. **Authenticated Vercel Functions:** `/api/plaid/link-token` calls Plaid `/link/token/create` with `products: ['transactions']`, `country_codes: ['CA']`, a stable `client_user_id` based on the signed-in Supabase user, and the webhook URL. `/api/plaid/exchange` accepts the short-lived public token from Link, calls `/item/public_token/exchange`, encrypts the returned access token, and stores the Item under that user. Authenticate each browser request with a Supabase access token and verify the user on the server. Do not trust a user ID sent in a request body.
3. **Sync and webhook handling:** call `/transactions/sync` once after connection and persist its `next_cursor`. On `SYNC_UPDATES_AVAILABLE`, verify Plaid's `Plaid-Verification` signature against the **raw request body**, look up the Item, then process every page of `added`, `modified`, and `removed` transactions before committing a new cursor. Use database transactions or another idempotent scheme so retries cannot duplicate entries. Plaid may remove a pending transaction and add a posted replacement; reconcile using `pending_transaction_id` when available. Do not count both. See [sync](https://plaid.com/docs/transactions/), [transaction states](https://plaid.com/docs/transactions/transactions-data/), and [webhook verification](https://plaid.com/docs/api/webhooks/webhook-verification/).
4. **Pockit review UI:** add **Connect bank**, connection status, last sync time, **Review imported transactions**, category rules, **Reconnect**, and **Disconnect** in Settings/Activity. Show pending items distinctly. Preserve manual and CSV entries and offer a duplicate-review flow before combining them with bank entries. Never silently mark a goal paid or bill paid because a similar bank amount appears. Let the user confirm a match.
5. **Removal and account deletion:** Disconnect must call Plaid `/item/remove` on the server and remove the encrypted token. Decide whether to retain imported transaction history and tell the user. Before deleting a Pockit account, remove every Plaid Item so monthly billing ends, then delete Pockit data. An RLS cascade alone does not remove the Plaid subscription. [Plaid billing](https://plaid.com/docs/account/billing/).
6. **Tests:** Sandbox Link success/exit/reconnect, invalid auth, duplicate Item, empty history, paginated sync, repeated/out-of-order webhooks, pending-to-posted replacement, modified/removed transactions, CSV overlap, category overrides, disconnect, and account deletion. Include phone-width tests for the Link return flow and transaction review.

## What to do right now

Use **Activity → Import CSV** with one export from your bank. Confirm its Date, Description/Payee, and Amount or Debit/Credit columns, then review the preview before importing. This gives the most useful part of bank connection—less typing—without adding a paid, sensitive integration. When you decide to pay for or trial a provider, this guide is the implementation checklist; adding Plaid keys alone will not create the feature.
